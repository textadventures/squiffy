# Squiffy 7 editor

The Squiffy editor at app.squiffystory.com (#278), on the same stack and app shell as Quest Viva's editor: SvelteKit + Skeleton, with CodeMirror 6. It replaced the 6.x editor in 7.0. The plan is in the comments on #278.

```bash
npm run dev     # http://localhost:5180
npm run check   # svelte-check
npm test
```

## How it fits together

- **Projects** are a `ProjectFileSystem` from `@textadventures/project-fs` plus the path of the main `.squiffy` file (`src/lib/project.svelte.ts`). With a `squiffy.json` project file (#361), the main file is its `main`, and every `.squiffy`, `.css` and `.js` file not in its `exclude` is part of the story. Without one, the main file is the one remembered in the browser (a browser story's `meta.json`, or the recent folders list), and it `@import`s the others. New stories get a `squiffy.json`. In a folder without one, adding a second `.squiffy` file or starring another file offers to add one (`offerProjectFile`), asking first, with a checklist, if there are other `.squiffy` files already. A new `squiffy.json` excludes the stylesheets and scripts the story doesn't `@import` (the language worker's `getStoryFiles`), and a new stylesheet or script only gets an `@import` when there's no `squiffy.json`. Starring a file rewrites `main`, and the files panel's Exclude from story / Include in story edit `exclude`. Each open file has a tab (which can be dragged into another order) and its own editor, so it keeps its cursor and undo history, and saves on its own. Images and other assets are files in the project too, managed from the Assets dialog (`AssetManagerModal.svelte`, from Quest Viva's), and referred to by their path from the main file's folder. They come from a folder opened with File System Access (Chromium), or the browser's origin-private file system (New, and Open file, which imports a file into a new story there), under `stories/`. A story kept in the browser shows a reminder to download a copy (`BackupBanner.svelte`) once it's been changed, and again a week after a download or Dismiss. Edits autosave a second after typing stops. Changes made outside the editor (by an AI agent, a text editor, git) are picked up as they happen where the file system can be watched (the desktop app), and otherwise when the window gets the focus (`src/lib/disk-changes.ts`). An open file with no unsaved changes reloads, as one undoable step; one with unsaved changes stops saving and shows a bar (`DiskChangeBar.svelte`) to use the changed file or keep the editor's. A file deleted outside the editor isn't put back unless the author says to. Before each save the file is read back, so a change the watcher missed isn't saved over either.
- **The language service** (`squiffy-compiler/language-service`) runs in a Web Worker (`src/lib/language/worker.ts`). It reads project files by calling back to the page (`src/lib/rpc.ts`), since some back ends, such as the Electron bridge, only exist there. The page sends it the text being edited as it changes.
- **Publish to textadventures.co.uk** (`src/lib/publish-online.ts`, `src/components/PublishOnlineModal.svelte`): the editor has no login there, so it uploads the published zip with no credentials and gets back a page on textadventures.co.uk for the author to open, where their own login finishes publishing it. The dialog then asks the site what became of the upload, to say when it's published. The story's `id` in `squiffy.json`, which the packager writes into the page as its IFID, is how the site knows an update from a new story, so a story with no `squiffy.json` is given one first. `VITE_PUBLISH_API_URL` points a development build at a local copy of the site. The design is `docs/one-click-publish.md` in the textadventures.co.uk repo.
- **Export** (`src/lib/export.ts`): the File menu publishes the story with `@textadventures/squiffy-packager` (HTML and JavaScript as a zip, one HTML file, or the JavaScript), in the language worker, from its existing analysis; the packager is loaded only when it's needed. Download project zips every file, with unsaved changes, and Open file reads such a zip back as a new story, which is how to keep a copy of a story kept in the browser. Its main file is the one `squiffy.json` names, if there is one. A zip with no `.squiffy` file in it is checked for a Quest gamebook (`.aslx`) or a Twine story, which are converted (`readZip` in `src/lib/project.svelte.ts`).
- **Offline:** `src/service-worker.ts` (SvelteKit's own service worker support, not `vite-plugin-pwa`) caches every file of the version when it installs, plus worker chunks SvelteKit's list leaves out the first time they're fetched, and serves the app's page for any route when there's no network. A new version waits until the update banner's Reload (`src/lib/updates.svelte.ts`, `UpdateBanner.svelte`). With `static/manifest.webmanifest` and the icons, the editor can be installed as an app, as the 6.x editor can.
- **The desktop app** (`desktop/`, #276) runs this editor in Electron. `src/lib/desktop.ts` detects it (`desktopApi()`), and there projects are folders on disk through project-fs's Electron bridge: New story asks for a name and makes a folder of that name (`NewStoryDialog.svelte`), Open file opens a `.squiffy` file's folder or unpacks a project zip into one, the recent folders come from the main process, Show in Finder (`folderReveal`) shows a file or the story's folder, and there are no stories kept in the browser and no service worker. Opening from the desktop app is in two steps (`pickDesktop…`, then `openPicked`), so the story that's open is saved and closed only once another's been picked. `src/lib/desktop-shell.ts` carries out the native menu's commands and saves before the window closes. See `desktop/README.md`.
- **Made with Squiffy** (`src/lib/featured-games.svelte.ts`): the home page shows four of the games featured for Squiffy on textadventures.co.uk (Admin → Featured Games there), from its `api/featured/squiffy`, chosen at random. The call sends `source` (`web` or `electron`), `version` and the desktop app's `platform`, which is how textadventures.co.uk counts the editor's use (Admin → App Usage). The last list is kept in localStorage so the games show at once, and they're hidden if the call fails. `VITE_FEATURED_API_URL` points a development build at a local copy of textadventures.co.uk.
- **Recent folders** (`src/lib/recent.ts`): folders opened with File System Access, kept in IndexedDB, are listed on the home page. Opening one asks the browser for permission again if it needs to. The editor's URL has the folder's id, so a reload reopens it while the browser still allows it.
- **The preview** (`src/components/PreviewPanel.svelte`) runs the story in squiffy-runtime's preview page, in a sandboxed `srcdoc` iframe, through `squiffy-runtime/preview-host`. The worker compiles it from the language service's analysis (`compile` in `src/lib/language/worker.ts`), so the story isn't parsed twice. The story's assets go to the preview as Blobs. Edits hot-update the running story; following a link in the preview moves the editor there, opening the file it's in. The page is loaded only when the preview first opens.
- **Problems** (`src/components/ProblemsPanel.svelte`): every diagnostic in the story, from the worker's `getProblems()` (each file in the analysis, with its diagnostics and code actions; `src/lib/problems.ts` pairs fixes with diagnostics, sharing `fixesByDiagnostic` with the lint markers). The page reads them again once typing pauses, for the toolbar's count, and the panel under the editor lists them with their fixes as buttons (Ctrl/Cmd+Shift+M, instead of CodeMirror's own one-file lint panel). A fix is only applied if the files it changes are as they were when it was made.
- **Find in Files** (`src/components/FindInFilesPanel.svelte`, Ctrl/Cmd+Shift+F): a search of every text file in the project outside `build/` (`src/lib/find-in-files.ts`), with `searchText` from `@textadventures/editor-search`, so it matches as the editor's Find panel does. The page searches again when the search, the list of files or an open file's text changes; open files are searched as they are in their editors. Its Replace row replaces one match or all of them (`replaceChanges` and `replaceInText` from the same package): an open file is changed in its editor, as one step to undo, and others on disk, after a confirmation that says so.
- **The story map** (`src/components/MapPanel.svelte`, #380) draws the language service's `getStoryGraph()` with `@textadventures/graph-map`'s `GraphMap` (`graph-map/`). `src/lib/story-map.ts` turns the story graph into the map's nodes and edges: sections ranked by the longest way to them from the start (leaving out links back round loops, so links point down the map), passages hanging under their sections, broken links as red markers, and unreachable sections as a group of their own. A long story's rows fold into columns side by side (graph-map's `aspect`), and long links are faint. The page reads the graph again once typing pauses, while the map's open. Positions the author has chosen are saved in `squiffy.json`'s `map`, by section and passage name; a section without a name of its own is saved under its label (`+++Day Two`, `--- after cave`), since the names the story gives those (`_continue2`) shift when one's added above (`sectionKeys`). A story without a `squiffy.json` gets one when something's first moved, excluding any `.squiffy` files that aren't part of the story now (from the analysis), so the story doesn't change; if the story has an error, so that isn't certain, the author is asked with `offerProjectFile` instead; renames are spotted by comparing graphs (a section that's gone and a new one with its header on the same line), so a section keeps its place however it's renamed. Links and sections added from the map are text edits, through the same `applyEdits` as rename. The preview's `onVisited` gives the map its playthrough trace.
- **The code editor** (`src/components/CodeEditor.svelte`, from Quest Viva's) takes its extensions from outside: the highlighting mode from `@textadventures/squiffy-codemirror` (`codemirror-lang/`, shared with the docs site's editable samples), and the language features from `src/lib/language/codemirror.ts`, which sends the editor's text to the worker before each query.

## Language features

| | |
|---|---|
| Problems | Lint markers, with quick fixes: create a missing section or passage, convert Squiffy 5 syntax, remove an `@import` that `squiffy.json` makes unneeded. Open files are checked again when another file changes |
| Completion | Section and passage names in links, attributes after `@set` and friends, snippets (Ctrl+Space) |
| Hover | The start of the section or passage a link goes to |
| Go to definition | F12, or Ctrl/Cmd+click |
| Find references | Shift+F12, in a panel under the editor |
| Rename | F2, across every link to the section or passage |
| Right-click menu | Go to definition, Find references and Rename, then cut, copy, paste and Find (`src/components/ContextMenu.svelte`, from the `languageCommands` facet). Shift+right-click, and a long press on a touchscreen, get the browser's menu |
| Keyboard shortcuts | A dialog from the ⋯ menu and the desktop app's Help menu, listing the editor's shortcuts and the most useful of CodeMirror's (`src/lib/shortcuts.ts`, whose test checks CodeMirror still binds them) |
| Folding | Sections and passages |
| Go to section or passage | Ctrl/Cmd+Shift+O, the outline's search box (which filters the map too) |
| Story map | Sections, passages and links, drawn from the story as it's typed. Click to go to code; drag to link or add sections |
| Run | Ctrl/Cmd+Enter from the start; Ctrl/Cmd+Shift+Enter from the section the cursor is in |
| Add | A section or passage (from the selection, if there is one), or a snippet: the 6.x editor's built-in ones and the story's own `[snippet:...]` blocks |
| Squiffy 5 | Opening a file that uses the Squiffy 5 text processor offers to convert all of it |
| Twine | Open file converts a Twine story (Twee, or published or archive HTML) into a new story in the browser, or a folder, with `src/lib/twine-import.ts` and the compiler's `convertTwine` |

Parts copied from Quest Viva's `src/AppShell` are noted in their comments. Fixes to the shared parts (`app.css`, `theme-store.ts`, `CodeEditor.svelte`, `codemirror-theme.ts`, `DropdownMenu.svelte`) may need porting between the two.

## Deployment

`deploy-app.yml` builds this for each release and uploads it to the `squiffy-app` Cloudflare Pages project: stable releases to app.squiffystory.com, and prereleases to app-beta.squiffystory.com, whose home page says it's the beta (`VITE_BETA_APP`). `squiffy-app` also builds a preview for every PR and push. Its build settings:

| Setting | Value |
|---|---|
| Root directory | (the repo root) |
| Build command | `npx lerna run build --scope @textadventures/squiffy-app --include-dependencies` |
| Build output directory | `app/build` |

It has no `404.html`, so Pages serves `index.html` for every path, which the app's client-side routing needs. `static/_headers` caches SvelteKit's hashed assets for a year.

### From the 6.x editor

The 6.x editor ran at the same addresses, so:

- `static/sw.js` replaces its service worker (Workbox, at `/sw.js`), which would otherwise keep serving the 6.x editor from its cache. It clears the 6.x caches, unregisters itself and reloads the page.
- Its unsaved work (idb-keyval's default store, key `autosave`) is offered on the home page, to open in the browser (`src/lib/legacy.ts`).
