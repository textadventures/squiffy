import {Aside} from "@astrojs/starlight/components";

Squiffy can convert a [Twine](https://twinery.org/) story into a Squiffy story. It reads stories written in the two most popular story formats, **Harlowe** (Twine's default) and **SugarCube**, and converts their passages, links and macros to Squiffy's sections, links and helpers.

If you're new to Squiffy, see [Coming from Twine](/coming-from-twine/) for how it compares to Twine.

## Converting a story

You can convert a story from either of the files Twine gives you:

- **The published HTML file**, from **Build > Publish to File** in Twine, or an archive from **Library > Archive**. If you only have a game you've played online, this is the file to save.
- **A Twee file** (`.twee` or `.tw`), from **Build > Export as Twee** in Twine 2.6 or later, or the file you build with [Tweego](https://www.motoslave.net/tweego/).

Then either:

- In the [editor](/editor/), choose **Open file** on the home page and pick the Twine file. The editor says what it is and asks before converting it. On the web, the converted story is kept in your browser. In the [desktop app](/desktop-app/), you choose a folder to put it in.
- With the [command-line tool](/cli/#converting-from-twine), run:

  ```bash
  npx @textadventures/squiffy-cli mygame.html --convert-twine
  ```

  This puts the converted story in a new folder next to the file, called `mygame`. Use `--out` to choose another folder.

## What you get

The converted story is a folder with:

- `story.squiffy`, the story itself. Each Twine passage becomes a section with the same name.
- `squiffy.json`, the [project file](/multiple-files/). It also keeps where the passages were on Twine's story map, so the editor's [story map](/story-map/) is laid out the way you arranged it in Twine, stretched sideways a little to fit the map's wider boxes. If you never arranged the passages in Twine, or the Twee file doesn't say where they go, the map lays the story out itself. **Lay out again**, above the map, swaps Twine's arrangement for the map's own.
- `story.css`, the story's stylesheet, with any `<style>`s from its passages, if it has one. It's part of the story: see [Styles](#styles).
- `story.js`, the story's JavaScript, if it has some. It isn't part of the story yet: see [JavaScript](#javascript) below.
- `twine-import.txt`, which lists everything that couldn't be converted exactly, passage by passage.

Twine shows one passage at a time, so the story starts with a [master section](/basic-concepts/#master-sections-and-passages) that clears the screen before each section. Delete its `@clear` if you'd rather the story scrolled, as Squiffy stories usually do.

Anything that couldn't be converted at all is kept in the story as a comment, so nothing's lost:

```squiffy
{{!-- Twine: (alert: "Watch out!") --}}
```

Search for `Twine:` to find them all. A converted story opens on the editor's [story map](/story-map/), full screen, as that's how you're used to seeing it. It's a good way to get to know the converted story, and to spot links that go nowhere. Double-click a section to [write it beside the map](/story-map/#writing-on-the-map), or use the button above the map to see the script.

<Aside>
Play the story through after converting it. Twine and Squiffy work differently in places, so some things are converted to the nearest thing Squiffy has, rather than exactly: these are listed in `twine-import.txt` too.
</Aside>

## How Harlowe converts

| Harlowe | Squiffy |
|---|---|
| `[[Go in->Cave]]`, `[[Cave<-Go in]]`, `[[Cave]]` | `[[Go in]](Cave)`, `[[Cave]]` |
| `(set: $gold to 10)` at the start of a passage | `@set gold = 10` |
| `(set: $gold to it + 5)` later on | `{{inc "gold" 5}}` |
| `(set: $bag to it + (a: "key"))` | `{{append "bag" "key"}}` |
| `$name`, `(print: $gold * 2)` | `{{name}}`, `{{= gold * 2}}` |
| `(if: $gold > 5)[...](else-if: ...)[...](else:)[...]` | `{{#if gold > 5}}...{{else if ...}}...{{else}}...{{/if}}` |
| `$a is 1 or 2`, `$bag contains "key"`, `$bag's length`, `visits` | `a = 1 or a = 2`, `bag contains "key"`, `bag.length`, `(visits "This passage")` |
| `(uppercase:)`, `(lowercase:)`, `(upperfirst:)` | `(upper ...)`, `(lower ...)`, `(capitalise ...)` |
| `(round:)`, `(floor:)`, `(ceil:)`, `(abs:)`, `(min:)`, `(max:)` | `(round ...)`, `(floor ...)` and so on. On its own in the text, `(round: $money)` shows its value: `{{round money}}` |
| `(cond: $hp > 0, "alive", "dead")` | `hp > 0 ? "alive" : "dead"` |
| `(display: "Map")` | `{{embed "Map"}}` |
| A custom macro: `(set: $say to (macro: str-type _who, [...]))`, `($say: "Ann")` | A section for the macro, `[[macro say]]:`, and `{{embed "macro say" who="Ann"}}`. Its parameters become the embed's [parameters](/basic-concepts/#parameters), and what it outputs with `(output:)` or `(output-data:)` is its text. A macro that takes any number of values (`...`), one kept in a temporary variable, and a call to a macro inside an expression, aren't converted |
| `(go-to: "End")`, `(after: 2s)[(go-to: "End")]` | `{{goto "End"}}`, `{{goto "End" after=2000}}` |
| `(after: $wait * 1s)[...]` | `{{#animate "fadeIn" start=(wait * 1000)}}...{{/animate}}` |
| `(live: 1s)[...]`, `(stop:)` | [`{{#every 1000}}...{{/every}}`](/dynamic-text/#repeating-text), `{{stop}}` |
| `(link: "Buy")[(set: $gold to it - 5)(go-to: "Shop")]` | `[[Buy]](Shop, gold -= 5)` |
| `(link: "Open")[It's empty.]`, `(link-reveal:)` | A [passage](/basic-concepts/#passages) link that [replaces](/dynamic-text/#replace) the link with the text |
| Named hooks, `(replace: ?door)`, `(show: ?note)` | [`{{#label}}` and `{{#replace}}`](/dynamic-text/#replace) |
| `(click: ?door)[...]`, `(click: "lamp")[...]` | A passage link on the hook or text |
| `(click: ?page)[...]` | A **Continue** link |
| `(either: "a", "b")`, `(random: 1, 6)` | `{{random (array "a" "b")}}`, `{{random (array 1 2 3 4 5 6)}}` |
| `(cycling-link: bind $size, "S", "L")` | `{{rotate (array "S" "L") set="size"}}` |
| `(input-box: bind $name)`, `(dropdown:)` | `<input data-attribute="name">`, `<select>` (see [User input](/player-input/)) |
| `(for: each _item, ...$bag)[_item]`, `(for: _n where _n > 2, ...$list)[...]` | [`{{#each bag}}{{this}}{{/each}}`](/attributes/#going-through-an-array), with `{{#if this > 2}}` for `where` |
| `(joined: ", ", ...$bag)`, `(sorted: ...$bag)`, `(shuffled: ...$bag)`, `(count: $bag, "coin")`, `(range: 1, $n)` | `(join bag ", ")`, `(sort bag)`, `(shuffle bag)`, `(count bag "coin")`, `(range 1 n)` |
| `$bag's last`, `$bag's 2ndlast` | `(last bag)`, `bag[bag.length - 2]` |
| `(set: $hero to (dm: "hp", 10))`, `$hero's hp`, `$party's 1st's name` | `@set hero = { hp: 10 }`, `{{hero.hp}}`, `{{= party[0].name}}`: see [Objects](/attributes/#objects) |
| `(storylet:)` and `(link-storylet:)` | A link to each storylet whose condition is true |
| `''bold''`, `//italic//`, `(text-colour: red)[...]` | Markdown and HTML |
| A passage's tags, and stylesheet rules for them, like `tw-story[tags~="dark"]` | `@class dark`, and `body:has(.dark)`: see [Styles](#styles) |
| Passages tagged `header`, `footer` and `startup` | The master section, an `{{embed}}` at the end of each section, and the start section |
| The [Harlowe Audio Library](https://twinelab.net/harlowe-audio/)'s `(track: "theme", "loop", true)` and `(track: "theme", "play")` | `@music theme.mp3`, or `{{music "theme.mp3"}}` later on: see [Sound](#sound) |
| `(track: "theme", "stop")`, `(track: "door", "play")` | `@music stop`, `@sound door.mp3` |

## How SugarCube converts

| SugarCube | Squiffy |
|---|---|
| `[[Go in\|Cave]]`, `[[Go in->Cave]]`, `[[Cave]]` | `[[Go in]](Cave)`, `[[Cave]]` |
| `[[Buy\|Shop][$gold -= 5]]` | `[[Buy]](Shop, gold -= 5)` |
| `<<set $gold to 10>>` at the start of a passage | `@set gold = 10` |
| `<<set $gold += 5>>`, `<<run $bag.push("key")>>` later on | `{{inc "gold" 5}}`, `{{append "bag" "key"}}` |
| `$name`, `<<print $gold * 2>>` | `{{name}}`, `{{= gold * 2}}` |
| `<<if $gold gt 5>>...<<elseif ...>>...<<else>>...<</if>>`, `<<switch>>` | `{{#if gold > 5}}...{{else if ...}}...{{else}}...{{/if}}` |
| `visited("Cave")`, `turns()`, `$bag.includes("key")`, `$bag.length` | `(visits "Cave")`, `turns`, `bag contains "key"`, `bag.length` |
| `$name.toUpperCase()`, `.toLowerCase()`, `.toUpperFirst()` | `(upper name)`, `(lower name)`, `(capitalise name)` |
| `$name.indexOf("x") != -1` (or `=== -1`) | `name contains "x"` (or `not name contains "x"`) |
| `Math.round()`, `Math.floor()`, `Math.ceil()`, `Math.abs()`, `Math.min()`, `Math.max()` | `(round ...)`, `(floor ...)` and so on |
| `$hp > 0 ? "alive" : "dead"` | `hp > 0 ? "alive" : "dead"` |
| `Object.keys($hero).length` | `(length "hero")` |
| `<<include "Map">>` | `{{embed "Map"}}` |
| `<<goto "End">>`, `<<timed 2s>><<goto "End">><</timed>>` | `{{goto "End"}}`, `{{goto "End" after=2000}}` |
| `<<timed $textSpeed>>...<<next>>...<</timed>>` | `{{#animate "fadeIn" start=textSpeed}}`, for each part. A delay like `"3s"` in a variable works as it is |
| `<<repeat 1s>>...<</repeat>>`, `<<stop>>` | [`{{#every 1000 append=true}}...{{/every}}`](/dynamic-text/#repeating-text), `{{stop}}` |
| `<<link "Buy" "Shop">><<set $gold -= 5>><</link>>` | `[[Buy]](Shop, gold -= 5)` |
| `<<linkreplace "Open">>It's empty.<</linkreplace>>` | A passage link that replaces the link with the text |
| `<<do tag "map">>...<</do>>`, and `<<redo "map">>` | `{{live "redo_map" passage="do"}}`, with what was in the `<<do>>` in the passage `[do]`, which `{{inc "redo_map"}}` shows again. `<<redo>>` with no tags shows every `<<do>>` again. One in a widget that uses `_args`, or in a loop, is shown once |
| `<span id="box">`, `<<replace "#box">>` | `{{#label "box"}}`, `{{#replace "box"}}` |
| `either("a", "b")`, `random(1, 6)` | `(random (array "a" "b"))`, `(random (array 1 2 3 4 5 6))` |
| `<<cycle "$size">>`, `<<textbox "$name">>`, `<<listbox>>` | `{{rotate ... set="size"}}`, `<input data-attribute="name">`, `<select>` |
| `<<textbox "$name" "" "Next">>`, which goes to a passage when Enter is pressed | `<input data-attribute="name" data-section="Next">` |
| `<<for _i, _item range $bag>>`, `<<for _i to 0; _i lt $bag.length; _i++>>` | [`{{#each bag}}`](/attributes/#going-through-an-array), with `_item` and `$bag[_i]` as `{{this}}`, and `_i` as `{{@index}}` |
| `<<for _i to 1; _i lte $n; _i++>>`, counting up or down by 1 | `{{#each (range 1 n)}}`, with `_i` as `{{this}}` |
| `<<for _i range 5>>`, going through a number | `{{#each (range 0 4)}}`, with `_i` as `{{this}}` |
| `$bag.join()`, `.sort()`, `.shuffle()`, `.slice()`, `.indexOf()`, `.count()`, `.first()`, `.last()` | `(join bag ",")`, `(sort bag)`, `(shuffle bag)`, `(slice bag ...)`, `(indexof bag ...)`, `(count bag ...)`, `(first bag)`, `(last bag)`. Squiffy's `sort` and `shuffle` don't change the array, so `<<run $bag.sort()>>` on its own isn't converted |
| `<<set $hero to { hp: 10 }>>`, `$hero.hp`, `$inv[_i].name` | `@set hero = { hp: 10 }`, `{{hero.hp}}`, `{{= inv[i].name}}`: see [Objects](/attributes/#objects) |
| Widgets: `<<say "Ann">>` | A section for each widget, and `{{embed "widget say" args=(array "Ann")}}`, with the arguments as a [parameter](/basic-concepts/#parameters), so `_args[0]` is `args[0]` |
| Container widgets: `<<say "Ann">>Hello!<</say>>`, and `_contents` | `{{#embed "widget say" args=(array "Ann")}}Hello!{{/embed}}`, and [`{{content}}`](/basic-concepts/#wrapping-text) |
| `''bold''`, `//italic//`, `@@color:red;...@@` | Markdown and HTML |
| A passage's tags, and stylesheet rules for them, like `body[data-tags~="dark"]` or `body.dark` | `@class dark`, and `body:has(.dark)`: see [Styles](#styles) |
| `<<addclass "body" "dark">>`, `<<removeclass "body" "dark">>`, `<<toggleclass "body" "dark">>` | `{{addclass "dark"}}`, `{{removeclass "dark"}}`, `{{toggleclass "dark"}}`. On anything but the page (`body`, `html`, `#story` or `#passages`), they aren't converted |
| `StoryInit`, `PassageHeader`, `PassageFooter` | The start section, the master section, an `{{embed}}` at the end of each section |
| `StoryCaption`, `StoryBanner` | A [panel](/buttons-panels-settings/#panels) beside the story, rendered again after each section and passage. Links in it don't work |
| `Setting.addToggle()`, `Setting.addList()`, `Setting.addRange()` in the story's JavaScript, and `settings.fontSize` | [Player settings](/buttons-panels-settings/#player-settings) in `squiffy.json`, and `settings.fontSize`: see [JavaScript](#javascript) |
| `memorize("endings", ...)`, `recall("endings")`, `forget("endings")` | [Attributes that last between playthroughs](/attributes/#attributes-that-last-between-playthroughs), listed under `persistent` in `squiffy.json`: `@set endings = ...`, `endings`, `{{forget "endings"}}`. `memorize(key, Object.assign(recall(key, {}), { pebbles: true }))` is `@set endings.pebbles = true`. A `recall()` with a default value other than nothing isn't converted |
| `<<link "Options">><<run UI.settings()>><</link>>`, and the same with `UI.restart()` and `UI.saves()` | `{{settings text="Options"}}`, `{{restart text="..."}}`, `{{saves text="..."}}` |
| `<<audio "theme" loop play>>`, `<<audio "theme" stop>>` | `@music theme.mp3`, `@music stop`, or `{{music "theme.mp3"}}` and `{{stopmusic}}` later on: see [Sound](#sound) |
| `<<audio "door" play>>`, `<<audio "door" volume 0.5 play>>` | `@sound door.mp3`, `{{sound "door.mp3" volume=0.5}}` |
| `<<audio "theme" fadeoverto 3 0>>` | `{{stopmusic fade=3}}` |
| `<<audio "door" stop>>`, `<<masteraudio stop>>`, `(masteraudio: "stopall")` | `@sound stop` or `{{stopsounds}}`, which stops every sound playing once, and for `masteraudio`, `@music stop` or `{{stopmusic}}` too |

### Sound

A track that the story sets to loop anywhere becomes [music](/images-and-files/#music-and-sound), which keeps playing from one section to the next until it's changed or stopped. Any other track becomes a sound, which plays once. At the start of a passage, they're `@music` and `@sound`, and later on, `{{music}}`, `{{stopmusic}}`, `{{sound}}` and `{{stopsounds}}`.

The tracks get their files from SugarCube's `<<cacheaudio "theme" "music/theme.mp3">>`, or the Harlowe Audio Library's `hal.tracks` passage and `(newtrack:)`. Where a track has more than one file, the MP3 is used. The sound files aren't copied, so put them in the story's folder, where the converted story expects to find them.

Squiffy fades from one piece of music to the next by itself, and it can't pause a track or change the volume of music. Squiffy stops every sound that plays once at the same time, so stopping one track stops the others too: if the story has more than one, `twine-import.txt` says so. The volume of music is left out, and the rest are left as comments, and they're listed in `twine-import.txt` too.

## What doesn't convert

These are left as comments, and listed in `twine-import.txt`:

- **JavaScript written for Harlowe or SugarCube**, such as SugarCube's `<<script>>`, `setup` and `State`. Squiffy can't run it: see [JavaScript](#javascript).
- **SugarCube's `StoryMenu`.** Its links go to other passages, which Squiffy's [panels](/buttons-panels-settings/#panels) don't do. A panel can show a passage from a button in the header instead.
- **Playlists, audio groups and changing all the sound at once**, such as SugarCube's `<<playlist>>` and `<<masteraudio>>`, or the Harlowe Audio Library's `(playlist:)` and `(masteraudio:)`. Pausing, muting and starting a track part of the way through aren't converted either. See [Sound](#sound) for what is.
- **`<<return>>` and `<<back>>`.** A screen the player visits and leaves, like an inventory, is better as a [panel](/buttons-panels-settings/#panels): see [Left out on purpose](/coming-from-twine/#left-out-on-purpose). Squiffy has its own Back button for undoing moves. Saving and loading from the story's text, such as Harlowe's `(save-game:)`, isn't converted either: players use Squiffy's **Save** button instead.
- **Loops that don't go through an array or a number, or count by 1**, such as `<<for _i lt 4>>`, and `<<break>>` and `<<continue>>`. Rewrite them with [`{{#each}}`](/attributes/#going-through-an-array). A link in a loop can set attributes to the item, but not to a value inside it, and if it does more than that, it can't use the item, because what it does is in a passage or section of its own.
- **Setting a value inside an object by a name or position in a variable**, such as `<<set $inv[_i].name to "rope">>`, anywhere but at the start of a passage, where it becomes an `@set`. Squiffy's `{{set}}` takes a fixed name.
- **Harlowe's datasets**, and JavaScript's object methods, such as `Object.keys()`.
- **Harlowe's more unusual hooks and changers**, such as `(enchant:)` on anything but how text looks, and `(append:)` on a hook in another passage.

Harlowe's `(text-style:)` styles become HTML tags (`"bold"` is `<b>`) or [`{{#style}}`](/dynamic-text/#text-effects) effects, such as `"shudder"`, `"emboss"` and `"double-underline"`. A `(transition:)` around a whole passage, as in `(t8n: "dissolve")+(t8n-time: 2s)[...]`, becomes [`@transition`](/dynamic-text/#transitions) in its section, as `@transition fade 2s`. Other changers that only change how something looks, such as `(link-style:)`, `(box:)`, transitions for part of a passage, and `(transition-arrive:)` and `(transition-depart:)` on links, are left out, and the text they changed is kept.

### JavaScript

A Twine story's JavaScript is written for its story format, so it won't work in Squiffy as it is. It's put in `story.js` so you have it, but `squiffy.json` leaves it out of the story. To use some of it, change it to use Squiffy's [JavaScript functions](/javascript/), then remove `story.js` from `exclude` in `squiffy.json` (in the editor, choose **Include in story** from its menu in the files list).

A `<script>` in a passage is different, as it's usually ordinary JavaScript that changes the page, such as text that types itself out. It runs when its section is shown, once the section's text is on the page, using [`squiffy.ui.afterWrite`](/javascript/#running-javascript-after-the-text). A `<script>` that uses the story format's JavaScript (such as `State`, `setup` or jQuery's `$`), or is inside a macro or hook, so it only ran some of the time, goes in `story.js` instead, with a comment saying which passage it was in. A `<script>` that loads a file, with `src`, is left as a comment.

SugarCube's settings are the exception: `Setting.addToggle()`, `Setting.addList()` and `Setting.addRange()` become [player settings](/buttons-panels-settings/#player-settings) in `squiffy.json`, with their labels, defaults and lists of options (written in the call, or in a variable the script sets to a list). Their `onInit` and `onChange` functions are JavaScript, so they aren't converted, and `twine-import.txt` lists them. They usually change the page, such as its font size, which the setting's classes can do instead: a setting called `fontSize` puts a class such as `setting-fontSize-125-` on the story, which your stylesheet can use. See [Styling with settings](/buttons-panels-settings/#styling-with-settings).

### Styles

The story's stylesheet is in `story.css`, which is part of the story. A `<style>` in a passage goes there too, with a comment saying which passage it was in, so it applies to the whole story, not only while that passage is shown.

Rules for Twine's own elements become rules for Squiffy's:

| Harlowe | SugarCube | Squiffy |
|---------|-----------|---------|
| `tw-story`, the page | | `body` |
| | `#story`, around the passages | `#squiffy-container` |
| | `#passages` | `#squiffy`, the story's element |
| `tw-passage` | `.passage` | `.squiffy-output-section`, a section's text |
| `tw-link`, `.enchantment-link` | `.link-internal`, `.macro-link` | `.squiffy-link` |
| `tw-sidebar` | | `#squiffy-header`, with the Back and Restart buttons |

Only the selectors change, so check how it looks: a rule for `#story` that makes room for SugarCube's sidebar, for example, might not suit Squiffy's page. Rules for other parts of Twine's page, such as SugarCube's `#ui-bar` and dialogs, or Harlowe's `tw-hook`, have nothing to match in Squiffy, and `twine-import.txt` lists them. See [Customising styles](/styling/) for Squiffy's.

A passage's tags become [`@class`](/styling/#changing-the-look-for-a-scene) in its section, and [`@tag`](/basic-concepts/#listing-passages-and-tagging-them), so the story can list its sections by them, except the ones that mean something to Twine or the story format, such as `widget`, `nobr` and `Twine.image`. Rules for tags, such as Harlowe's `tw-story[tags~="dark"]` and SugarCube's `body[data-tags~="dark"]` and `body.dark`, become rules for the class: `body:has(.dark)` for the whole page, as `tw-story`, `body` and `html` are, and `.dark` for the passage, such as `tw-passage[tags~="dark"]` or `.passage[data-tags~="dark"]`. See [Changing the look for a scene](/styling/#changing-the-look-for-a-scene).
