If you want more control over how your Squiffy story is presented, you can embed it in your own HTML page. This allows you to customize the layout, add your own styling, or integrate the story into an existing website.

## Basic setup

First, export your story using the CLI with `--scriptonly`:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --scriptonly
```

This creates `story.js` containing your compiled story.

You'll also need the Squiffy runtime and its stylesheet. You can either:
- Run a full export first and keep `squiffy.runtime.global.js` and `squiffy.css`
- Or load them from a CDN such as jsDelivr, which serves the [`squiffy-runtime`](https://www.npmjs.com/package/squiffy-runtime) npm package. Use the same version of Squiffy that you compiled your story with. For the current version ({version}), that's:

<Code lang="html" code={`<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/squiffy-runtime@${version}/dist/squiffy.runtime.css">
<script src="https://cdn.jsdelivr.net/npm/squiffy-runtime@${version}/dist/squiffy.runtime.global.js"></script>`} />

Here's a minimal HTML page that runs a Squiffy story:

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My Story</title>
    <link rel="stylesheet" href="squiffy.css">
    <script src="squiffy.runtime.global.js"></script>
    <script src="story.js"></script>
</head>
<body>
    <div id="squiffy"></div>
    <script>
        document.addEventListener('DOMContentLoaded', async function () {
            const squiffyApi = await squiffyRuntime.init({
                element: document.getElementById('squiffy'),
                story: story,
            });
            await squiffyApi.begin();
        });
    </script>
</body>
</html>
```

## Using Vite

If you're building a web app with [Vite](https://vite.dev), the Squiffy Vite plugin lets you import `.squiffy` files directly. They're compiled as part of your build, so there's no separate export step:

```bash
npm install --save-dev @textadventures/vite-plugin-squiffy
npm install squiffy-runtime
```

Add the plugin to `vite.config.ts`:

```ts
import { defineConfig } from "vite";
import squiffy from "@textadventures/vite-plugin-squiffy";

export default defineConfig({
    plugins: [squiffy()],
});
```

Then import your story and pass it to `init()`:

```ts
import { init } from "squiffy-runtime";
import "squiffy-runtime/squiffy.runtime.css";
import { story } from "./mygame.squiffy";

const squiffyApi = await init({
    element: document.getElementById("squiffy")!,
    story,
});
await squiffyApi.begin();
```

If the story's folder has a [`squiffy.json` project file](/project-file/), import its main file to get the whole story, with its stylesheets and scripts, which Vite bundles. Keep the story in a folder of its own, such as `src/story`, since every `.css` and `.js` file in the folder is part of it. The plugin leaves out Vite's output and `public` folders and its config file.

While Vite's dev server is running, it recompiles the story whenever you save a `.squiffy` file that's part of it. With a few more lines, you can update the running story without losing the player's progress. See the [plugin's README](https://github.com/textadventures/squiffy/tree/main/vite-plugin) for that, and for TypeScript setup. There's a complete example in [`examples/vite-app`](https://github.com/textadventures/squiffy/tree/main/examples/vite-app).

The options and API below are the same whichever way you load the story. With Vite, `init` is imported from `squiffy-runtime` rather than called as `squiffyRuntime.init`.

## Initialization options

The `squiffyRuntime.init()` function accepts an options object:

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `element` | `HTMLElement` | (required) | The container element for the story output |
| `story` | `Story` | (required) | The compiled story object (from `story.js`) |
| `persist` | `boolean` | `true` | Whether to save state to localStorage |
| `storyId` | `string` | The `id` in the story's [`squiffy.json`](/project-file/#id), or else the URL path (or an ID made when the story is compiled, when it's opened from a local file) | Key used for localStorage (allows multiple stories on same domain) |
| `scroll` | `string` | `"body"` | Scroll behavior: `"body"`, `"element"`, or `"none"` |
| `onSet` | `function` | - | Callback when an attribute is set |
| `resolveAssetUrl` | `function` | - | Maps an image or other file path used in the story to the URL to load it from. See [Asset URLs](#asset-urls) |
| `strings` | `object` | - | The page's text in another language, with the [names in `squiffy.json`](/buttons-panels-settings/#the-pages-text-in-another-language). Used for the text of [`{{restart}}`, `{{saves}}` and `{{settings}}`](/basic-concepts/#restarting-and-saving-from-the-story) links, and the dialogs they open. Anything left out is in English |

### Persistence

By default, Squiffy saves the player's progress to localStorage, so they can return to where they left off. The `storyId` option determines the storage key:

```javascript
const squiffyApi = await squiffyRuntime.init({
    element: document.getElementById('squiffy'),
    story: story,
    persist: true,
    storyId: 'my-unique-story-id',
});
```

The browser only keeps a few megabytes in localStorage for each site, shared by every story on it. If it's full, the story carries on, but its progress stops being kept there until the story's restarted, and a warning says so in the browser's console. Reloading the page then starts the story again. Saved games, from [`getSave()`](#getsave) or [the Saved games dialog](#the-saved-games-dialog), aren't affected.

Set `persist: false` to disable saving:

```javascript
const squiffyApi = await squiffyRuntime.init({
    element: document.getElementById('squiffy'),
    story: story,
    persist: false,
});
```

### Scroll behavior

The `scroll` option controls how the page scrolls when new content appears:

- `"body"` (default) - Scrolls the page body
- `"element"` - Scrolls within the container element (useful for fixed-height containers)
- `"none"` - No automatic scrolling

```javascript
const squiffyApi = await squiffyRuntime.init({
    element: document.getElementById('squiffy'),
    story: story,
    scroll: 'element',
});
```

### Asset URLs

By default, file paths in the story, like `cat.png` in `![A cat](cat.png)`, load relative to the page. If your files live somewhere else, pass `resolveAssetUrl` to map each path to a URL:

```javascript
const squiffyApi = await squiffyRuntime.init({
    element: document.getElementById('squiffy'),
    story: story,
    resolveAssetUrl: (path) => 'https://cdn.example.com/my-story/' + path,
});
```

It's applied to `src`, `srcset` and `poster` attributes (so images, audio, video and `<source>` elements), and to `url(...)` in inline `style` attributes, including inside `{{#animate}}` blocks. It's called with the path as written in the story, with any `%20`-style encoding decoded. Return the path unchanged to leave it as it is.

It isn't called for:
- absolute URLs (`http:`, `https:`, `data:`, `blob:` and other schemes) or protocol-relative ones (`//example.com/...`)
- links (`href`)
- `<style>` elements and stylesheets

When the player returns to a saved story, its saved output is resolved again, so URLs that only last for a session, like `blob:` URLs, still work.

## API methods

The `init()` function returns a `SquiffyApi` object with these methods:

### begin()

Starts or resumes the story. Call this after initialization:

```javascript
await squiffyApi.begin();
```

To start somewhere other than the beginning, pass a section, and optionally a passage in it. This ignores any saved game:

```javascript
await squiffyApi.begin({ section: 'cellar', passage: 'look around' });
```

### restart()

Restarts the story from the beginning, clearing saved state:

```javascript
squiffyApi.restart();
```

### get(attribute)

Gets the value of a story attribute:

```javascript
const score = squiffyApi.get('score');
const hasKey = squiffyApi.get('hasKey');
```

### set(attribute, value)

Sets a story attribute:

```javascript
squiffyApi.set('score', 100);
squiffyApi.set('playerName', 'Alice');
```

### goBack()

Goes back to the previous section or passage (undo):

```javascript
squiffyApi.goBack();
```

### canGoBack()

Returns whether there's anything to go back to, for example to enable a Back button when the story starts. After that, the `canGoBackChanged` event says when it changes:

```javascript
backButton.disabled = !squiffyApi.canGoBack();
```

### getSave()

Returns the game as it is now, as an object you can keep, for example as JSON in a file or a database, and load again with `loadSave()`. It has the story's [`id`](/buttons-panels-settings/#saved-games), where the player was, the start of the text they were reading (`summary`), when it was saved, and every attribute, including the text on screen:

```javascript
const save = squiffyApi.getSave();
localStorage.setItem('my-save', JSON.stringify(save));
```

### loadSave(save)

Carries on from a saved game, replacing the game as it is now. A save from a story with a different `id` isn't loaded:

```javascript
const result = await squiffyApi.loadSave(JSON.parse(localStorage.getItem('my-save')));
if (!result.success) {
    console.log(result.error); // "wrongStory", "notASave" if it isn't a saved game, or "newerSave" if it's from a newer Squiffy
}
```

### renderPassage(name)

Returns a passage in the master section `[[]]` as HTML, with the attributes as they are now, as the published page's [panels](/buttons-panels-settings/#panels) show it. It doesn't change the story: `{{set}}` and the like are ignored, the passage's `@set` and JavaScript don't run, and its links are disabled.

```javascript
statusElement.innerHTML = squiffyApi.renderPassage('status');
```

### isMuted() and setMuted(muted)

Whether the story's [music and sounds](/images-and-files/#music-and-sound) are muted, for a mute button. With `persist` on, it's remembered for the story, and restarting doesn't change it.

```javascript
muteButton.addEventListener('click', () => {
    squiffyApi.setMuted(!squiffyApi.isMuted());
});
```

### usesSound()

Returns whether the story plays music or sounds: it names a sound file, or has played one. The `sound` event says when something plays, for a mute button that only shows when it's needed.

### getSettings(), getSetting(name), setSetting(name, value) and resetSettings()

The story's [player settings](/buttons-panels-settings/#player-settings), for your own settings controls. `getSettings()` returns them as they are in `squiffy.json`, and `getSetting()` returns one's value, which is its default until the player changes it. `setSetting()` changes it, as the Settings dialog does, and ignores a value the setting can't have. `resetSettings()` puts them all back to their defaults.

```javascript
squiffyApi.setSetting('textSize', 'Large');
squiffyApi.getSetting('textSize');  // "Large"
```

With `persist` on, settings are remembered for the story. Going back, restarting and loading a saved game don't change them, and saved games don't include them.

### dispose()

Stops the story's music and sounds for good, for when you're replacing the story with another one.

## Panels

The published page's [panels](/buttons-panels-settings/#panels) are part of the runtime too. `createPanels()` adds a button for each panel to the start of an element, such as your page's header, and puts side panels in an `<aside class="squiffy-panels-side">` at the end of another, which gets the class `squiffy-has-side`. They're rendered again whenever the story moves on:

```javascript
squiffyRuntime.createPanels(squiffyApi, {
    panels: story.panels,  // from squiffy.json
    buttons: document.getElementById('header'),
    side: document.getElementById('container'),
});
```

| Option | Description |
|---|---|
| `panels` | The panels, as in `squiffy.json`. A compiled story has them as `story.panels` |
| `buttons` | Where the panels' buttons go: at the start of this element |
| `side` | Where side panels go. Without it, side panels only have their buttons |
| `strings` | The dialog's text: `close`, as in [`squiffy.json`](/buttons-panels-settings/#the-pages-text-in-another-language) |
| `container` | Where to put the dialog in the page. The end of the body by default |

It returns an object with `refresh()`, which renders the panels again, `open(passage)`, which opens a panel's dialog, and `dispose()`, which takes them all off the page. Their styles are in `squiffy.runtime.css`, apart from the published page's layout, which is in `squiffy.page.css`.

## The Saved games dialog

The published page's [Saved games](/buttons-panels-settings/#saved-games) dialog is part of the runtime, so you can use it too. `createSavesDialog()` adds it to the page, and `open()` shows it:

```javascript
const savesDialog = squiffyRuntime.createSavesDialog(squiffyApi);
saveButton.addEventListener('click', () => savesDialog.open());
```

The saves are kept in the browser's IndexedDB, under the page's path. These options change that:

| Option | Description |
|---|---|
| `key` | Which story the saves are for, if not the page's path. The published page gives the story's [`id`](/project-file/#id), so its saves are kept wherever it's put |
| `slots` | Somewhere else to keep the saves: an object with `list`, `get`, `add`, `overwrite`, `rename` and `delete` methods, like the runtime's `memorySaveSlots()` |
| `strings` | The dialog's text, using the [names in `squiffy.json`](/buttons-panels-settings/#the-pages-text-in-another-language) |
| `fileName` | The name Save to file gives the file, before `.squiffy-save`. The page's title by default |
| `container` | Where to put the dialog in the page. The end of the body by default |

Its styles are in `squiffy.runtime.css`.

## The Settings dialog

The published page's Settings dialog, for a story with [player settings](/buttons-panels-settings/#player-settings), is part of the runtime too. `createSettingsDialog()` adds it to the page, and `open()` shows it:

```javascript
if (story.settings) {
    const settingsDialog = squiffyRuntime.createSettingsDialog(squiffyApi);
    settingsButton.addEventListener('click', () => settingsDialog.open());
}
```

| Option | Description |
|---|---|
| `strings` | The dialog's text: `settings`, `resetSettings` and `close`, as in [`squiffy.json`](/buttons-panels-settings/#the-pages-text-in-another-language) |
| `container` | Where to put the dialog in the page. The end of the body by default |

Its styles are in `squiffy.runtime.css`.

## Asking the player

`confirmDialog()` asks the player a question, such as whether to restart, in a dialog styled like the Saved games one, rather than with the browser's `confirm()`. It returns a promise of whether they went ahead:

```javascript
if (await squiffyRuntime.confirmDialog({ message: 'Are you sure you want to restart?', confirm: 'Restart' })) {
    squiffyApi.restart();
}
```

| Option | Description |
|---|---|
| `message` | The question |
| `confirm` | The text of the button that goes ahead |
| `cancel` | The text of the button that doesn't. "Cancel" by default |
| `danger` | `true` to colour the button that goes ahead as a warning, for something that can't be undone |
| `container` | Where to put the dialog in the page. The end of the body by default |

Escape, Cancel and clicking outside the dialog all answer no. Its styles are in `squiffy.runtime.css`.

## Events

You can listen for events using `on()`, `off()`, and `once()`:

### linkClick

Fired when a story link is clicked:

```javascript
squiffyApi.on('linkClick', (event) => {
    console.log('Link type:', event.linkType); // "section", "passage", "rotate" or "sequence"
});
```

### set

Fired when an attribute value changes:

```javascript
squiffyApi.on('set', (event) => {
    console.log(`${event.attribute} = ${event.value}`);
});
```

### canGoBackChanged

Fired when the ability to go back changes:

```javascript
squiffyApi.on('canGoBackChanged', (event) => {
    backButton.disabled = !event.canGoBack;
});
```

### navigated

Fired when a section or passage is shown, and when going back returns to one. `passage` is only set for a passage:

```javascript
squiffyApi.on('navigated', (event) => {
    console.log(`Now in ${event.section}`, event.passage);
});
```

### storyUpdated

Fired when `update()` changes the story, for example after an edit in the editor:

```javascript
squiffyApi.on('storyUpdated', () => {
    statusElement.innerHTML = squiffyApi.renderPassage('status');
});
```

### sound

Fired when music or a sound starts playing, even if it's muted:

```javascript
squiffyApi.on('sound', () => {
    muteButton.hidden = false;
});
```

### restartRequested and savesRequested

Fired when the player clicks a [`{{restart}}` or `{{saves}}`](/basic-concepts/#restarting-and-saving-from-the-story) link. If nothing is listening, the runtime handles the link itself: it asks the player whether they're sure, then restarts, or opens a Saved games dialog of its own. Listen for them to use your page's own, for example the same dialog as your Save button:

```javascript
squiffyApi.on('restartRequested', async (event) => {
    // event.confirm is false for {{restart confirm=false}}
    if (!event.confirm || await squiffyRuntime.confirmDialog({ message: 'Start again?', confirm: 'Restart' })) {
        squiffyApi.restart();
    }
});
squiffyApi.on('savesRequested', () => savesDialog.open());
```

### settingsRequested

Fired when the player clicks a [`{{settings}}`](/basic-concepts/#restarting-and-saving-from-the-story) link. If nothing is listening, the runtime opens a Settings dialog of its own. Listen for it to open your page's own:

```javascript
squiffyApi.on('settingsRequested', () => settingsDialog.open());
```

### settingChanged

Fired when a [player setting](/buttons-panels-settings/#player-settings) changes, with its name and new value. Putting the settings back to their defaults fires it for each one that changes.

```javascript
squiffyApi.on('settingChanged', (event) => {
    console.log(`${event.name} is now ${event.value}`);
});
```

### squiffy:ready

When `init()` has set the story up, the story's element sends a `squiffy:ready` DOM event, which bubbles up to `document`. It's how the story's [own scripts](/javascript/#scripts-on-the-page) get the story, so they work on your page too, as long as the element is in the page when you call `init()`. They get a smaller API than `init()` returns, without `begin()`, `restart()` and the like, which are your page's to call.

### Unsubscribing

The `on()` method returns an unsubscribe function:

```javascript
const unsubscribe = squiffyApi.on('linkClick', handler);

// Later, to stop listening:
unsubscribe();
```

Or use `off()`:

```javascript
squiffyApi.off('linkClick', handler);
```

## Complete example

Here's a more complete example with custom controls:

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My Story</title>
    <link rel="stylesheet" href="squiffy.css">
    <script src="squiffy.runtime.global.js"></script>
    <script src="story.js"></script>
    <style>
        #controls {
            padding: 10px;
            background: #f0f0f0;
            margin-bottom: 20px;
        }
        #squiffy {
            max-width: 800px;
            margin: 0 auto;
            padding: 20px;
        }
        button:disabled {
            opacity: 0.5;
        }
    </style>
</head>
<body>
    <div id="controls">
        <button id="restart">Restart</button>
        <button id="back" disabled>Back</button>
        <span id="status"></span>
    </div>
    <div id="squiffy"></div>
    <script>
        document.addEventListener('DOMContentLoaded', async function () {
            const squiffyApi = await squiffyRuntime.init({
                element: document.getElementById('squiffy'),
                story: story,
                persist: true,
                storyId: window.location.pathname,
            });

            const backButton = document.getElementById('back');
            const statusEl = document.getElementById('status');

            // Restart button
            document.getElementById('restart').addEventListener('click', async function () {
                if (await squiffyRuntime.confirmDialog({ message: 'Are you sure you want to restart?', confirm: 'Restart' })) {
                    squiffyApi.restart();
                }
            });

            // Back button
            backButton.addEventListener('click', function () {
                squiffyApi.goBack();
            });

            // Update back button state
            squiffyApi.on('canGoBackChanged', (event) => {
                backButton.disabled = !event.canGoBack;
            });

            // Show score changes
            squiffyApi.on('set', (event) => {
                if (event.attribute === 'score') {
                    statusEl.textContent = `Score: ${event.value}`;
                }
            });

            await squiffyApi.begin();
            // A saved game may have somewhere to go back to
            backButton.disabled = !squiffyApi.canGoBack();
        });
    </script>
</body>
</html>
```

## Styling

Squiffy adds CSS classes to its output that you can style:

- `.squiffy-output-section` - Container for each section
- `.squiffy-output-passage` - Container for each passage
- `.squiffy-link` - All clickable links
- `.squiffy-link.disabled` - Links that have been clicked/disabled

You can include the default styles (`squiffy.css` from a full export, or `squiffy.runtime.css` from the CDN) and override what you want to change in a stylesheet of your own, linked after them, or write your own styles from scratch. See [Customising styles](/styling/) for a reference to the default styles.

The colours in `squiffy.runtime.css` follow your page's [`color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/color-scheme). A page that doesn't set one is light, so an embedded story stays light unless your page supports dark mode, for example with `:root { color-scheme: light dark; }`. The page layout of an exported story, including its background and text colours, is in `squiffy.page.css` in the same package.
