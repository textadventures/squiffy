You can write Hello World with no markup at all:

<Sample script="Hello, World!

"></Sample>
    
You can format text using [Markdown](https://daringfireball.net/projects/markdown/syntax), and also use HTML.

<Sample script="Here is some **bold text** and some _italic text_.

A list:
- Item 1
- Item 2
- Item 3

A link to [Google](https://www.google.com).

Using a `&lt;span&gt;` tag to &lt;span style=&quot;color: red&quot;&gt;change the colour&lt;/span&gt; of some text.
"></Sample>

To create interactive stories, you'll need to add some links. There are two types of text block you can use in Squiffy:

- **Sections** are the main units of text.
- **Passages** are smaller units which exist within sections.

Taking the player to a new section will deactivate all previous links, so use a new section when the player has taken some action to move the story forward.

Within a section, you can link to passages. After the player clicks a link to a passage, links to other passages in the same section will remain active.

## Sections

Section names must be unique within a story. Set up a section using double square brackets, followed by a colon. To link to a section, use double square brackets.

<Sample script="Do you want to have the [[roast chicken]] or skip straight to [[dessert]]?
    
[[roast chicken]]:
This plate of roast chicken looks delicious.

[[dessert]]:
Three different flavours of ice cream - yum!"></Sample>

To use different link text, put the name of the section in brackets afterwards.

```squiffy
This is [[how to use custom link text]](section2).
```

## Passages

Set up a passage using single square brackets, followed by a colon. Passages can link to further passages. After the player clicks a link to a passage, that link is deactivated, so the player can only click it once. To link to a passage, use single square brackets.

<Sample script="Looking around the room, you can see a [TV], a [book] and a piece of [paper] with some handwriting scribbled on it.

[TV]:
Covered in dust and the plug is missing.

[book]:
It's a book of magic tricks. Maybe you should [open] it?

[open]:
The cover opens up to reveal the pages all glued together, with an empty key-shaped hole cut out.

[paper]:
&quot;Gone out for a walk. May be a while.&quot;"></Sample>

Passage links can be explored in any order - in the example above, the player might look at the book first, then look at the TV, then open the book. Only after clicking a link to another section will any remaining passage links be deactivated.

Passage names must be unique within their section.

To use different link text, put the name of the passage in brackets afterwards.

```squiffy
This is [how to use custom link text](passage1).
```

### Passages you can click again

To let the player click a passage's links as often as they like, put `@repeat` on a line on its own in the passage. Each click shows the passage again. This suits things the player might want to look at more than once, such as a clue, or a character who says something different each time you talk to them:

<Sample script="A [guard] blocks the door.

[guard]:
@repeat
@inc guard_talks
{{#if guard_talks = 1}}&quot;Move along.&quot;{{else if guard_talks = 2}}&quot;I said, move along.&quot;{{else}}&quot;Fine. The password is *swordfish*.&quot;{{deactivate}}{{/if}}"></Sample>

Once the guard has given up the password, there's nothing more to say, so `{{deactivate}}` turns off the links to the guard: see [Turning off passage links](#turning-off-passage-links).

Clicks on a passage with `@repeat` don't count towards [`@1`, `@2`... and `@last`](#running-a-passage-after-some-clicks), and `@last` doesn't wait for it to be clicked.

### Turning off passage links

`{{deactivate "name"}}` turns off the links to a passage in this section, as if the player had already clicked them. Use it when one choice rules out another. Here, opening the box means the player can't smash it any more:

<Sample script="There's a locked box. You could [open it with the key], or [smash it].

[open it with the key]:
{{deactivate &quot;smash it&quot;}}The lid opens neatly.

[smash it]:
{{deactivate &quot;open it with the key&quot;}}Splinters everywhere. Whatever was inside is broken."></Sample>

You can name more than one passage, as in `{{deactivate "b" "c"}}`. In a passage, `{{deactivate}}` on its own turns off the links to that passage. As it's a helper, it can go inside `{{#if}}`, so that it only happens sometimes.

It turns off the links that are on the screen when the passage is shown: a link to the passage that appears later is a new link, which the player can click. Going back with the Back button turns the links on again.

### Listing passages, and tagging them

`(passages)` is a list of the passages in this section, in the order they're written, so the story can choose among them without listing their names again. Put `@tag` on a line in a passage to give it tags, separated by spaces, and `(passages tagged="passenger")` lists only the passages with that tag. `untagged="asleep"` leaves out the ones with that tag:

<Sample script="The train pulls in. In the carriage there's {{#join (passages tagged=&quot;passenger&quot;) &quot;, &quot; &quot; and &quot;}}{{passage this}}{{/join}}.

As you sit down, {{random (passages tagged=&quot;passenger&quot; untagged=&quot;asleep&quot;)}} looks up.

[a man in a hat]:
@tag passenger
He tips his hat to you.

[a woman with a dog]:
@tag passenger
The dog wags its tail.

[a sleeping student]:
@tag passenger asleep
He snores gently."></Sample>

- `(passages)` lists this section's passages, then the [master section's](#master-sections-and-passages), as the links in this section can reach both. `(passages "carriage")` lists the carriage section's passages, and `(passages "")` the master section's.
- The master passage and the [`@1`, `@last` and `@after`](#running-a-passage-after-some-clicks) passages aren't listed, as they aren't for linking to.
- `tagged` and `untagged` can each have more than one tag, separated by spaces: `tagged="passenger awake"` lists the passages with both.
- Sections can have tags too, with `@tag` in the section, and `(sections)` lists the story's sections, with `tagged=` and `untagged=` as for passages.
- `(tags "a man in a hat")` is a passage's or section's tags, as a list, so `{{#if (tags "a sleeping student") contains "asleep"}}` checks for one. `(tags)` on its own is this section's tags.

These are lists, so they work with the [array helpers](/helpers-reference/#array-management-helpers), such as `{{#each}}`, `join`, `random`, `shuffle` and `length`. In JavaScript, they're `squiffy.story.passages()`, `squiffy.story.sections()` and `squiffy.story.tags()`: see [JavaScript](/javascript/).

## Continue links

When you want a simple link that moves to the next part of your story, use `+++` followed by the link text. This creates both the link and a new section in one step.

<Sample script="This is the first part of my story.

+++Continue...

This is the second part.

+++I want to hear more...

Very well. Here is the third part."></Sample>

The `+++` syntax is a shorthand. Instead of writing:

```squiffy
This is the first part.

[[Continue...]](second part)

[[second part]]:
This is the second part.
```

You can simply write:

```squiffy
This is the first part.

+++Continue...

This is the second part.
```

Everything after `+++Continue...` until the next `+++` or `[[section]]:` becomes the content of the new section.

You can use directives like `@clear` or `@set` immediately after the `+++` line:

```squiffy
+++Next chapter...
@clear

The screen clears and this text appears fresh.
```

## Formatting links

Links can use Markdown and HTML, like any other text. To format a whole link, put the formatting around it:

<Sample script="Will you go **[[north]]** or _[[south]]_?

[[north]]:
It's cold up here.

[[south]]:
It's warm down here."></Sample>

You can also put the formatting inside the link text, when the link names where it goes. That works for section and passage links, and for `+++`:

<Sample script="The door is [**locked**](door). [[_Leave_]](outside)

[door]:
It won't budge.

+++**Continue...**

You're back where you started.

[[outside]]:
Fresh air at last."></Sample>

<Aside type="caution">
Don't put formatting inside a link that doesn't name where it goes. Squiffy takes the name from the link text, formatting and all, so `[[**north**]]` is a link to a section called "\*\*north\*\*", not "north". Write `**[[north]]**` or `[[**north**]](north)` instead.
</Aside>

## Section dividers and next-section links

Sometimes you need to link to the next section from inside a block helper like `{{#animate}}`. The `+++` syntax won't work there because it would split the section before the closing `{{/animate}}`.

For these cases, use `---` to start a new anonymous section, and `[[text>]]` to create a link that points to whatever section comes next.

<Sample script="{{#animate &quot;fadeIn&quot;}}
Welcome to the story!

[[Begin>]]
{{/animate}}

---

The adventure starts here.

[[Continue>]]

---

And the story continues..."></Sample>

The `>` at the end of the link text means "link to the next section". This is equivalent to:

```squiffy
{{#animate "fadeIn"}}
Welcome to the story!

[[Begin]](section2)
{{/animate}}

[[section2]]:
The adventure starts here.

[[Continue]](section3)

[[section3]]:
And the story continues...
```

You can also use the explicit form `[[link text]](>)` if you prefer, or if you need to set attributes:

```squiffy
[[Begin]](>, score=10)
```

## Go to another section

`{{goto "section name"}}` moves the story on to another section without the player clicking a link. It's most useful inside `{{#if}}`, for example to end the story when the player runs out of health:

<Sample script="[[start]]:
@set health = 1
A troll blocks the bridge. [[Fight it]](fight, health -= 1) or [[run away]](escape).

[[fight]]:
The troll swings its club.
{{#if health <= 0}}{{goto &quot;death&quot;}}{{else}}You duck just in time. [[Cross the bridge]](escape){{/if}}

[[death]]:
@end
Everything goes dark. THE END.

[[escape]]:
@end
You get away."></Sample>

The section with the `{{goto}}` is shown first, and the story moves on once it's been written. All of the section is shown, including any text after the `{{goto}}`, so put text the player shouldn't see when they move on in an `{{else}}`, as above.

To move on after a delay, add `after=` with a number of milliseconds, or a time like `"3s"`:

```squiffy
The lights go out.
{{goto "darkness" after=3000}}
```

If the player follows a link before then, the story doesn't move on. The delay can be an expression, such as `after=delay * 1000`. See [Moving on after a delay](/dynamic-text/#moving-on-after-a-delay).

`{{goto}}` only goes to sections. To show a passage's text, use [`{{embed}}`](#embed-text). The section name can come from an expression, so this goes to one of three sections at random:

```squiffy
{{goto (random (array "cave" "forest" "river"))}}
```

If the player goes back, they go back past sections and passages that moved on with `{{goto}}`, to where they last clicked a link.

<Aside>
A `{{goto}}` in the [master section](#master-sections-and-passages) runs in every section, including the one it goes to. Use [`at`](/helpers-reference/#navigation-helpers) to leave that one out: `{{#if health <= 0 and not (at "death")}}{{goto "death"}}{{/if}}`.
</Aside>

## Running a passage after some clicks

You can trigger a passage after the player has made a certain number of clicks within a section. For example, you can display some extra text, to indicate the passage of time. Or, the passage might run some JavaScript to automatically move the player to another section.

To count clicks across the whole story instead, use the [`turns` attribute](/attributes/#counting-turns).

In the example below, the text "We're nearly here. The train is pulling into the platform." is always written after the first passage click. After the second passage click, we are moved into the next section.

<Sample script="On the train you can see a [girl singing], a [man reading a book] and an [old woman].

[girl singing]:
She is nodding her head to the music in her enormous earphones, and singing badly out of tune.

[man reading a book]:
He's been reading the same page of *War and Peace* for a while now.

[old woman]:
She eyes you suspiciously, as if she has seen your type before.

[@1]:
We're nearly here. The train is pulling into the platform.

[@2]:
&#32;&#32;&#32;&#32;squiffy.story.go(&quot;station&quot;);

[[station]]:
We have now arrived at the station."></Sample>

You can also trigger a passage to be written only after all the passages in that section have been clicked on.

See the example below where after all passage links have been clicked the text "You have examined every item." will display.

<Sample script="Looking at the detective's desk you can see the following items to examine; a [photograph], a [file] and a [coffee mug].

[photograph]:
Looks like some kind of work celebration. The detective is in the middle of the picture holding a basket of fruit and other officers are toasting him.

[file]:
The file is empty. You notice though that the tab has your brother's name on it!

[coffee mug]:
It is just a coffee mug.

[@last]:
You have examined every item."></Sample>

### Running a passage after every click

`[@after]:` runs after every passage link the player clicks in its section, whichever it is. It's for something that happens on every click, such as time passing, without writing `[@1]:`, `[@2]:`, `[@3]:`... and working out how many clicks there can be.

<Sample script="The train rattles on. You watch the [girl singing], the [man reading a book] and the [old woman].

[girl singing]:
She is nodding her head to the music in her enormous earphones.

[man reading a book]:
He's been reading the same page of *War and Peace* for a while now.

[old woman]:
She eyes you suspiciously.

[@after]:
@inc minutes
{{= minutes}} {{= minutes = 1 ? &quot;minute&quot; : &quot;minutes&quot;}} have passed.

[@last]:
The train is pulling into the station."></Sample>

- It runs after the passage that was clicked, and before `[@1]`, `[@2]`... and `[@last]`, so `[@last]` can still finish the section with a [`{{goto}}`](#go-to-another-section).
- It runs after passages with [`@repeat`](#passages-you-can-click-again) too, although they don't count towards `[@1]`... and `[@last]`.
- In the [master section](#master-sections-and-passages), it runs after every passage in the story, after the section's own `[@after]`, if it has one.
- It doesn't run when the player goes to a section. For that, use the [master section](#master-sections-and-passages).

## Clear the screen

Any section or passage can clear the screen using @clear on a line on its own:

```squiffy
[[Chapter 2]]:
@clear
My first reaction to the explosion was...
```

To make the old text fade or slide away first, add [`@leave`](/dynamic-text/#when-the-screen-is-cleared).

`@clear` always clears the screen, even inside an `{{#if}}`, as directives always run. To clear it only some of the time, use `{{clear}}` instead. Here, getting off the train clears the screen, but changing platforms doesn't:

```squiffy
[[platform]]:
{{#if previous_section != "change"}}{{clear}}{{/if}}
I am standing on the platform. [[Change platforms]](change)

[[change]]:
I cross the bridge to the other side. [[Wait here]](platform)
```

`{{clear}}` clears everything shown before it, including any text before it in the same section, such as the master section's. Only what comes after it is shown.

## Endings

A section that has no links to another section is where the story stops. The editor warns about these "dead ends", in case you meant to add a link. If the section is one of your story's endings, say so with `@end` on a line on its own, and the warning goes away:

```squiffy
[[Fall into the river]]:
@end
The current carries you away. THE END.
```

An `@end` in one of a section's passages marks the whole section as an ending. `@end` doesn't change what the player sees.

### Restarting and saving from the story

A published story has Restart and Save buttons above it. To give the player those choices in the story itself, such as "Play again" at an ending, use `{{restart}}` and `{{saves}}`:

```squiffy
[[Fall into the river]]:
@end
The current carries you away. THE END.

{{restart text="Play again"}} or {{saves text="load a saved game"}}
```

`{{restart}}` asks the player whether they're sure, as the Restart button does. To restart straight away, add `confirm=false`: `{{restart text="Play again" confirm=false}}`. `{{saves}}` opens the [Saved games](/buttons-panels-settings/#saved-games) dialog, where the player can save or load a game. It works even if you've turned off the Save button, so you can offer saving only where it suits your story.

If your story has [player settings](/buttons-panels-settings/#player-settings), such as text size or content warnings, `{{settings}}` is a link that opens the Settings dialog, like the Settings button: `{{settings text="Choose your text size"}}`.

Without `text`, the links say "Restart", "Saved games" and "Settings", or the [`restart`, `saves` and `settings` text](/buttons-panels-settings/#the-pages-text-in-another-language) in your `squiffy.json`. Like other links, they can only be clicked while the player is still in their section.

## Embed text

You can embed text from another section, or from a passage in the current section, using `{{embed "section or passage name"}}`.

<Sample script="[[section1]]:
Here is some text from the next section: {{embed &quot;section2&quot;}}

Here is some text from a passage in this section: {{embed &quot;passage&quot;}}

[passage]:
Text from passage.

[[section2]]:
Text from next section."></Sample>

### Parameters

An embed can pass values to the text it shows, so one section can be used again and again with different words. Give each one a name: `{{embed "say" who="Ann" line="Hello!"}}`. The embedded text uses them like attributes, as `{{who}}` and `{{line}}`, and in conditions and calculations.

<Sample script="[[start]]:
@set gold = 10
{{embed &quot;say&quot; who=&quot;Ann&quot; line=&quot;Hello!&quot;}}

{{embed &quot;say&quot; who=&quot;Bob&quot; line=&quot;Spare some gold?&quot; asks=gold - 7}}

[[say]]:
**{{who}}:** {{line}}{{#if asks}} (He wants {{asks}} gold.){{/if}}"></Sample>

A parameter's value can be text, a number, an attribute or an expression, like `asks=gold - 7` or `items=["lamp", "key"]`.

Parameters belong to the embed:

- A parameter hides an attribute with the same name while the embedded text is shown, but doesn't change it. After the embed, `{{who}}` is the story's `who` again.
- Setting a parameter inside the embedded text, with `{{set}}`, `{{inc}}` and so on, changes it for the rest of that embed only. Setting any other attribute changes the story's, as usual.
- They aren't saved, and an embed inside the embedded text doesn't see them, unless it's given them too.
- A parameter that isn't given is the story's attribute with that name, if there is one.

### Wrapping text

An embed can also wrap some text, which the embedded text shows wherever it has `{{content}}`. This is useful for a frame, or a way of showing something, used all over the story:

<Sample script="[[start]]:
@set name = &quot;Ann&quot;
{{#embed &quot;speech&quot; who=&quot;Guard&quot;}}Halt! Who goes there?{{/embed}}

{{#embed &quot;speech&quot; who=&quot;You&quot;}}It's me, {{name}}.{{/embed}}

[[speech]]:
**{{who}}:** <q>{{content}}</q>"></Sample>

The wrapped text is part of the section it's written in, so its attributes are that section's: `{{name}}` there is the story's `name`, even if the embed has a parameter called `name`.

### Links in embedded text

Links to sections work anywhere. A link to a passage looks for the passage in the section the player is in when they click it, which isn't the one the text was embedded from. So a section that's embedded in other sections should link to sections, not its own passages. A passage's text is also shown after the embed has finished, so it can't use the embed's parameters, although the link to it can.

The editor doesn't say that a section that's only embedded can't be reached.

## Track which sections and passages have been seen

You can show different text depending on whether the player has seen a particular section or passage. See [Tracking sections and passages](/attributes/#tracking-sections-and-passages).

## Set the start section

By default, the story begins in the first section. You can choose a different section like this:

<Sample script="@start Beginning

[[some other section]]:
This section would normally be the start, but we have overridden it.

[[Beginning]]:
This is where the story begins."></Sample>

## Set the title

Set the title like this:

```squiffy
@title My Amazing Interactive Story
```

## Master sections and passages

An empty name for a section or passage creates a "master", which is triggered for every section or passage in the game. (A master passage defined in a named section will only be triggered for every passage in that section)

e.g. to clear the screen before every section, and to count how many sections the player has been through:

```squiffy
[[]]:
@clear
@inc sections_visited
```
