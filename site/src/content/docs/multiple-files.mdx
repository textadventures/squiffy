A story can be split across several `.squiffy` files. To make a folder of files one story, give it a [project file](/project-file/), `squiffy.json`, naming the story's main file:

```json
{
  "version": 1,
  "main": "story.squiffy"
}
```

Every `.squiffy` file in the folder and its subfolders is then part of the story, and so is every `.css` and `.js` file: see [Stylesheets and scripts](#stylesheets-and-scripts). You don't need to `@import` them. Every story made in the editor already has a `squiffy.json`. See [The project file](/project-file/) for how to add one, and what else it does.

- The main file comes first, then the other files in order of their paths. That order decides how `+++` sections are numbered and, if two sections have the same name, which one wins (you'll get a warning).
- The story starts in the main file, at its first section or its [`@start`](/basic-concepts/#set-the-start-section) section, and the main file's `@title` is the story's title. `@title` and `@start` in other files are ignored, with a warning.
- A section in one file can link to a section in any other.
- Paths to images and other files, and in `@import`, are relative to the main file's folder, whichever file they're in. So you can move a file into a subfolder without changing it.

## Stylesheets and scripts

<Screenshot name="files-new" alt="The + menu in the files list, offering a story file, a stylesheet or a script" />

With a `squiffy.json`, every `.css` file in the folder and its subfolders is one of the story's [stylesheets](/styling/), and every `.js` file is one of its [scripts](/javascript/). The published page links to each of them, as it does for an `@import`: stylesheets after Squiffy's own styles, so your rules take precedence, and scripts before the story starts.

- They're added in order of their paths. Order rarely matters for stylesheets, but a script that uses another, such as a library, needs to come after it. To choose the order, `@import` the ones that need to come first in the main file: anything `@import`ed comes before the rest, and nothing is added twice.
- A file you read with [`@ui filename.js`](/javascript/#running-code-when-the-story-starts) isn't added as a script too, so it doesn't run twice.
- The `build` folder next to `squiffy.json`, where the [command-line tool](/cli/#usage) puts the published story, is never part of it.
- Earlier versions of Squiffy wrote a published story's files next to its main file. So if there's an `index.html` there, the `story.js`, `style.css`, `squiffy.css`, `squiffy.runtime.js` and `squiffy.runtime.global.js` with it are taken to be an old copy of the published story, and aren't part of the story unless you `@import` them. You can delete them.
- To keep any other file out of the story, such as a library's demo files, list it under [`exclude`](#leaving-files-out).

## Leaving files out

To keep a `.squiffy`, `.css` or `.js` file in the folder without it being part of the story, list it under `exclude`. In the editor, choose **Exclude from story** from the file's menu in the files list.

<Screenshot name="files-excluded" alt="A stylesheet left out of the story, greyed out and marked excluded in the files list, with its menu open at Include in story" />

```json
{
  "version": 1,
  "main": "story.squiffy",
  "exclude": ["notes.squiffy", "drafts/**", "lib/demo.js"]
}
```

Paths are relative to the folder `squiffy.json` is in. `*` and `?` match within a file or folder name, and `**` across folders. Naming a folder leaves out everything in it, so `drafts` and `drafts/**` are the same. Files in `node_modules`, in folders whose names start with a dot, and in the `build` folder are always left out, as is [an old copy of the published story](#stylesheets-and-scripts). So is a folder with a `squiffy.json` of its own, which is another story.

## Building a story with a project file

With the [command-line tool](/cli/#usage), run it in the folder without a file name, or give it the folder or the main file. It puts the published story in a `build` folder next to `squiffy.json`. Give it any other `.squiffy` file, and it builds just that file, next to it, so several separate stories can still share a folder.

With the [Vite plugin](/embedding/#using-vite), import the main file. Keep the story in a folder of its own, away from your app's code, as every `.js` and `.css` file in the folder is part of the story.

## Importing files

Without a `squiffy.json`, a story is its main file and whatever that imports:

```squiffy
@import other_file.squiffy
```

This syntax also accepts wildcards, so you can include all .squiffy files in a directory:

```squiffy
@import *.squiffy
```

Without a `squiffy.json`, JavaScript and CSS files need an `@import` too:

```squiffy
@import my_script.js
@import my_style.css
```

In a story with a `squiffy.json`, an `@import` of a file that's already part of the story isn't needed, and the editor offers to remove it. An `@import` in the main file still adds the file at that point: a `.squiffy` file's sections go there in the story, and a stylesheet or script comes before the ones that aren't `@import`ed. You can also `@import` a file that `exclude` leaves out.
