---
title: Stories in several files
description: Splitting a story across files, stylesheets and scripts with a squiffy.json project file, or with @import
---


A story can be split across several `.squiffy` files. To make a folder of files one story, add a project file called `squiffy.json` to the folder, naming the story's main file:

```json
{
  "$schema": "https://squiffystory.com/schema/squiffy.json",
  "version": 1,
  "id": "0b7c6d9e-3f1a-4e2b-9c5d-8a7f6e5d4c3b",
  "main": "story.squiffy"
}
```

Every `.squiffy` file in the folder and its subfolders is then part of the story, and so is every `.css` and `.js` file: see [Stylesheets and scripts](#stylesheets-and-scripts). You don't need to `@import` them.

A `squiffy.json` also means the story uses Squiffy 7's rules for [setting attributes](/attributes/#setting-attributes), where text goes in quotes: `@set weapon = "sword"`. A story without one keeps the Squiffy 6 rules. See [Coming from Squiffy 6](/coming-from-squiffy-6/).

- The main file comes first, then the other files in order of their paths. That order decides how `+++` sections are numbered and, if two sections have the same name, which one wins (you'll get a warning).
- The story starts in the main file, at its first section or its [`@start`](/basic-concepts/#set-the-start-section) section, and the main file's `@title` is the story's title. `@title` and `@start` in other files are ignored, with a warning.
- A section in one file can link to a section in any other.
- Paths to images and other files, and in `@import`, are relative to the main file's folder, whichever file they're in. So you can move a file into a subfolder without changing it.
- `version` is the version of the project file format, which is 1. A version of Squiffy that doesn't know the version refuses to build the story, saying you need a newer Squiffy.
- `id` identifies your story, so a player's [saved game](#saved-games) can only be loaded into the story it came from. The editor and the command-line tool give a new `squiffy.json` a random one. Keep it the same when you publish a new version of your story, and don't copy it into another story.

The `$schema` line is optional. It lets text editors such as VS Code check the file and suggest what can go in it.

## Stylesheets and scripts

With a `squiffy.json`, every `.css` file in the folder and its subfolders is one of the story's [stylesheets](/styling/), and every `.js` file is one of its [scripts](/javascript/). The published page links to each of them, as it does for an `@import`: stylesheets after Squiffy's own styles, so your rules take precedence, and scripts before the story starts.

- They're added in order of their paths. Order rarely matters for stylesheets, but a script that uses another, such as a library, needs to come after it. To choose the order, `@import` the ones that need to come first in the main file: anything `@import`ed comes before the rest, and nothing is added twice.
- A file you read with [`@ui filename.js`](/javascript/#running-code-when-the-story-starts) isn't added as a script too, so it doesn't run twice.
- The `build` folder next to `squiffy.json`, where the [command-line tool](/cli/#stories-in-several-files) puts the published story, is never part of it.
- Earlier versions of Squiffy wrote a published story's files next to its main file. So if there's an `index.html` there, the `story.js`, `style.css`, `squiffy.runtime.js` and `squiffy.runtime.global.js` with it are taken to be an old copy of the published story, and aren't part of the story unless you `@import` them. You can delete them.
- To keep any other file out of the story, such as a library's demo files, list it under [`exclude`](#leaving-files-out).

## The Back button

A published story has a **Back** button, which lets the player undo their choices, a section or passage at a time. To leave it out, so that the player's choices are final, set `backButton` to `false`:

```json
{
  "version": 1,
  "main": "story.squiffy",
  "backButton": false
}
```

## Saved games

A published story has a **Save** button, which opens the player's list of saved games. They can save as often as they like, optionally giving each save a name, and later load, overwrite, rename or delete them. A save without a name is shown by the start of the text the player was reading, or by the heading it starts with. The player can also save the game to a file, and load it from a file, to keep it safe or carry on in another browser.

Saved games are kept in the player's browser, separately for each story. They're as well as the automatic save, which lets the player close the page and carry on where they left off: loading a saved game replaces it.

A saved game from a different story isn't loaded: the player is told it's for a different story. Squiffy tells them apart by their [`id`](#stories-in-several-files). A story without an `id` loads any saved game, so give yours one if it hasn't got one: any text will do, as long as no other story has it.

If you publish a new version of your story, players can still load their saved games, carrying on with the new version from where they were. If the section they were in has gone, the story starts again from the beginning, keeping their attributes.

To leave out the Save button, set `saveButton` to `false`:

```json
{
  "version": 1,
  "main": "story.squiffy",
  "saveButton": false
}
```

## Panels

A panel shows a passage that's always to hand, such as the player's stats, their inventory, a map or some help. It's rendered again each time the story moves on, so it's always up to date. List your panels under `panels`:

```json
{
  "version": 1,
  "main": "story.squiffy",
  "panels": [
    { "passage": "status", "label": "Status", "position": "side" },
    { "passage": "inventory", "label": "Inventory", "icon": "bag" },
    { "passage": "help", "label": "Help" }
  ]
}
```

Each panel's passage is in the [master section](/basic-concepts/#master-sections-and-passages) `[[]]`:

```squiffy
[[]]:

[status]:
**Gold:** {{gold}}

**Health:** {{health}}

[inventory]:
{{#each inventory}}
- {{this}}
{{else}}
You're carrying nothing.
{{/each}}

[help]:
Click a link to choose what happens next.
```

- `"position": "side"` shows the panel beside the story. On a narrower screen, such as a phone's, it's a button in the header instead, which shows the panel in a dialog.
- Any other panel is a button in the header, next to the Back and Restart buttons, which shows its passage in a dialog. The dialog follows the story while it's open.
- `label` is the button's text. To show an icon instead, with the label as its tooltip, give an `icon`: `bag`, `person`, `map`, `help`, `info`, `list`, `book`, `star` or `heart`.

A panel only shows its passage: it doesn't change the story. `{{set}}`, `{{goto}}` and the like are ignored, the passage's `@set` and JavaScript don't run, and its links don't work. Opening a panel isn't a move, so Back doesn't go back to it. A side panel whose text comes out empty is hidden, so `{{#if}}` can hide it until it has something to show.

To change how panels look, see [Panels](/styling/#panels) in Styling.

## The page's text in another language

A published story's buttons are icons, with a tooltip that says what each one does, which screen readers read out too. Clicking Restart asks the player whether they're sure. This text, and the text of the [Saved games](#saved-games) dialog and the [panels'](#panels) Close button, is in English unless you give your own under `strings`:

```json
{
  "version": 1,
  "main": "story.squiffy",
  "strings": {
    "back": "Retour",
    "restart": "Recommencer",
    "restartConfirm": "Voulez-vous vraiment recommencer ?",
    "switchToDark": "Passer en mode sombre",
    "switchToLight": "Passer en mode clair"
  }
}
```

| String | English |
|---|---|
| `back` | Back |
| `restart` | Restart |
| `restartConfirm` | Are you sure you want to restart? |
| `switchToDark` | Switch to dark mode |
| `switchToLight` | Switch to light mode |
| `saves` | Saved games |
| `saveName` | Name (optional) |
| `save` | Save |
| `noSaves` | No saved games yet. |
| `savedGame` | Saved game |
| `savedToday` | Today, [time] |
| `savedYesterday` | Yesterday, [time] |
| `load` | Load |
| `loadConfirm` | Load "[name]"? You'll lose anything you've done since you last saved. |
| `saveOptions` | Options for [name] |
| `overwrite` | Overwrite |
| `overwriteConfirm` | Overwrite "[name]"? |
| `rename` | Rename |
| `newName` | New name |
| `saveToFile` | Save to file |
| `loadFromFile` | Load from file |
| `delete` | Delete |
| `deleteConfirm` | Delete "[name]"? This can't be undone. |
| `cancel` | Cancel |
| `close` | Close |
| `wrongStory` | This saved game is for a different story. |
| `notASave` | This file isn't a saved game. |
| `cantSave` | The game couldn't be saved. Try Save to file instead. |

`[name]` is replaced with the name of the save, and `[time]` with the time it was saved.

Anything you leave out stays in English. A story without a `squiffy.json` is always in English.

## Leaving files out

To keep a `.squiffy`, `.css` or `.js` file in the folder without it being part of the story, list it under `exclude`. In the editor, choose **Exclude from story** from the file's menu in the files list.

```json
{
  "version": 1,
  "main": "story.squiffy",
  "exclude": ["notes.squiffy", "drafts/**", "lib/demo.js"]
}
```

Paths are relative to the folder `squiffy.json` is in. `*` and `?` match within a file or folder name, and `**` across folders. Naming a folder leaves out everything in it, so `drafts` and `drafts/**` are the same. Files in `node_modules`, in folders whose names start with a dot, and in the `build` folder are always left out, as is [an old copy of the published story](#stylesheets-and-scripts).

The editor also saves where you've put sections and passages on its [story map](/story-map/) in `squiffy.json`, under `map`. Only the editor uses it.

## Building a story with a project file

With the [command-line tool](/cli/#stories-in-several-files), run it in the folder without a file name, or give it the folder or the main file. It puts the published story in a `build` folder next to `squiffy.json`. Give it any other `.squiffy` file, and it builds just that file, next to it, so several separate stories can still share a folder.

With the [Vite plugin](/embedding/#using-vite), import the main file. Keep the story in a folder of its own, away from your app's code, as every `.js` and `.css` file in the folder is part of the story.

## Importing files

Without a `squiffy.json`, a story is its main file and whatever that imports:

```squiffy
@import other_file.squiffy
```

This syntax also accepts wildcards, so you can include all .squiffy files in a directory:

```squiffy
@import *.squiffy
```

Without a `squiffy.json`, JavaScript and CSS files need an `@import` too:

```squiffy
@import my_script.js
@import my_style.css
```

In a story with a `squiffy.json`, an `@import` of a file that's already part of the story isn't needed, and the editor offers to remove it. An `@import` in the main file still adds the file at that point: a `.squiffy` file's sections go there in the story, and a stylesheet or script comes before the ones that aren't `@import`ed. You can also `@import` a file that `exclude` leaves out.
