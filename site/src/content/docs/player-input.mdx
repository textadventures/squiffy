You can capture text input from players using HTML input elements. The value will be stored in an attribute that you can reference later in your story.

<Sample script="What is your name?

&lt;input type=&quot;text&quot; data-attribute=&quot;player_name&quot; placeholder=&quot;Enter your name...&quot;&gt;

[[Begin the adventure]]

[[Begin the adventure]]:
Welcome, {{player_name}}! Your adventure begins now."></Sample>

The `data-attribute` specifies which attribute will store the input value. You can then reference it using `{{player_name}}` or `{{get "player_name"}}`.

It can also be a value inside an [object](/attributes/#objects), as in `data-attribute="hero.name"`.

## Going on when Enter is pressed

Add `data-section` to a text box, and pressing Enter in it goes to that section, just as clicking a link to it would. `data-passage` shows a passage instead. Either way, what the player typed is stored first, so the section or passage can use it.

<Sample script="What is your name?

&lt;input type=&quot;text&quot; data-attribute=&quot;player_name&quot; data-section=&quot;begin&quot; required&gt;

[[begin]]:
Welcome, {{player_name}}!"></Sample>

Like a passage link, a text box with `data-passage` can only be used once, unless the passage has [`@repeat`](/basic-concepts/#passages-you-can-click-again), so the player can try again:

<Sample script="I'm thinking of a number between 1 and 10. &lt;input type=&quot;number&quot; data-attribute=&quot;guess&quot; data-passage=&quot;check&quot;&gt;

[check]:
@repeat
{{#if guess = &quot;7&quot;}}You got it!{{else}}It's not {{guess}}. Try again.{{/if}}"></Sample>

Enter doesn't do anything until every text box in the section is [filled in properly](#input-validation). A `<textarea>` doesn't go anywhere when Enter is pressed, as Enter starts a new line in it.

## Input Validation

Squiffy supports HTML5 input validation attributes. When validation attributes are present, section and passage links will be automatically disabled until all inputs pass validation.

Supported validation attributes include:
- `required` - field must be filled
- `minlength` / `maxlength` - text length constraints
- `min` / `max` - numeric constraints
- `pattern` - regular expression validation
- `type` - format validation (email, url, number, etc.)

<Sample script="Please tell us about yourself:

Name: &lt;input type=&quot;text&quot; data-attribute=&quot;name&quot; required minlength=&quot;2&quot; placeholder=&quot;At least 2 characters&quot;&gt;

Age: &lt;input type=&quot;number&quot; data-attribute=&quot;age&quot; required min=&quot;1&quot; max=&quot;120&quot;&gt;

Email: &lt;input type=&quot;email&quot; data-attribute=&quot;email&quot; required&gt;

[[Submit]]

[[Submit]]:
Thank you, {{name}}! We've recorded your information.

Age: {{age}}

Email: {{email}}"></Sample>

In this example, the [[Submit]] link will be disabled (grayed out and unclickable) until:
- The name is at least 2 characters long
- The age is a number between 1 and 120
- The email is in a valid email format

Invalid inputs are highlighted with a red border, while valid inputs show a green border. As the player types, the validation updates in real-time, and links automatically become clickable once all inputs are valid.

You can use other HTML input types as well:

&lt;/select&gt;

{{#if comments}}Your comment: {{comments}}{{/if}}"></Sample>
