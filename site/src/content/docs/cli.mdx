## Installing

As an alternative to the [web editor](https://app.squiffystory.com), Squiffy is also available as a command-line Node package. This runs on Windows, Mac and Linux.

To install the Squiffy compiler, first [install Node.js](https://nodejs.org/).

You can then run the CLI directly using `npx`:

```bash
npx @textadventures/squiffy-cli mygame.squiffy
```

Alternatively, install it globally:

```bash
npm install @textadventures/squiffy-cli -g
```

**If the install fails:** On a Mac or Linux, if you get an error installing, try using `sudo`:

```bash
sudo npm install @textadventures/squiffy-cli -g
```

## Usage

You can create a Squiffy file in any text editor - Notepad, [VS Code](https://code.visualstudio.com/), [Sublime Text](https://www.sublimetext.com/), TextEdit etc.

Squiffy files are text files with a `.squiffy` file extension.

To transform a Squiffy file into a working browser-based game, go to its directory in a command prompt and type:

```bash
npx @textadventures/squiffy-cli mygame.squiffy
```

Squiffy will write four files to the same folder as the script file:
- `index.html` - the main HTML page
- `style.css` - the stylesheet
- `story.js` - your compiled story
- `squiffy.runtime.global.js` - the Squiffy runtime

Launch `index.html` to play the game.

This folder of files can now be uploaded anywhere, and it will run entirely locally in the player's web browser (the source `.squiffy` script file does not need to be included).

The browser's local storage will be used to save the state of the game. This means the player can close their browser, and the next time they go back to that page, the game will resume from where they left off.

**Note: Even if you recompile a game, the previous state will still be loaded.** This means that after making a change to your game, you'll need to click the Restart button at the top of the screen to see your changes.

### Stories in several files

If your story is split across several `.squiffy` files with a [`squiffy.json` project file](/basic-concepts/#stories-in-several-files), run Squiffy in the story's folder without a file name:

```bash
npx @textadventures/squiffy-cli
```

Giving it the folder, or the main file named in `squiffy.json`, does the same. The files are written to the main file's folder.

Give it any other `.squiffy` file in the folder, and it builds just that file and whatever it `@import`s, as if there were no `squiffy.json`. Squiffy says when it does this. So a folder can still hold several separate stories.

### Errors and warnings

If your script has a problem, Squiffy prints it with the file and line number:

```text
WARNING: mygame.squiffy line 12: In section 'kitchen' there is a link to a section called [[cellar]], which doesn't exist
ERROR: mygame.squiffy line 30: Can't add passage "look" as no section has been created.
```

A warning, such as a link to a section or passage that doesn't exist, points at the line the problem is on, and the game is still created. A hint, such as an `@import` that isn't needed, is a suggestion. An error stops the game being created, so fix it and run Squiffy again.

## Output Formats

Squiffy supports different output formats depending on how you want to distribute your game.

### Standard (multiple files)

The default output creates four separate files as described above. This is ideal for:
- Hosting on a web server
- Situations where you want to customize the HTML or CSS
- Development and debugging (easier to inspect individual files)

### Single HTML file (inline)

Use `--inline` to create a single self-contained HTML file with all CSS, JavaScript, and story content embedded:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --inline
```

This creates just one file: `index.html`. This is ideal for:
- Easy sharing (just send one file)
- Uploading to platforms that only accept a single HTML file
- Offline distribution
- Embedding in other documents

### Zip file

Use `--zip` to also create a zip archive of the output files, called `output.zip`:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --zip
```

You can combine this with `--inline` to create a zip containing just the single HTML file:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --inline --zip
```

### Images and other files

Images, sounds and other files that your story [refers to](/basic-concepts/#images-and-other-files) are included automatically, as long as they're in the same folder as the `.squiffy` file or a folder below it:

- With the standard output, they're already in the right place, next to `index.html`.
- With `--zip`, they're added to `output.zip` at the same paths.
- With `--inline`, they're embedded in `index.html` as data URIs, so the single file still works on its own. This makes the file about a third bigger than the files themselves, so large sound or video files are better shared with `--zip`.

Squiffy looks for file names in your story text and JavaScript with these extensions: `apng`, `avif`, `bmp`, `gif`, `ico`, `jpeg`, `jpg`, `png`, `svg`, `webp`, `aac`, `flac`, `m4a`, `mp3`, `oga`, `ogg`, `opus`, `wav`, `weba`, `m4v`, `mp4`, `ogv`, `webm`, `vtt`, `otf`, `ttf`, `woff`, `woff2` and `pdf`. File names with spaces aren't found, so either avoid spaces or write them as `%20` (e.g. `my%20cat.png`).

## Options

### HTTP Server

Use `--serve` (or `-s`) to start a local HTTP server after compiling. Open the address it prints (e.g. `http://localhost:8282/`) in your browser to test your game:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --serve
```

Optionally specify a port using `--port` (or `-p`):

```bash
npx @textadventures/squiffy-cli mygame.squiffy --serve --port 3000
```

The default port is 8282.

### Script only

Use `--scriptonly` to generate *only* the `story.js` file, without overwriting the other files. This is useful when you've customized `index.html` or `style.css` and only want to update the story:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --scriptonly
```

You can optionally specify a custom filename:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --scriptonly myscript.js
```
### Converting from Twine

Use `--convert-twine` to convert a [Twine](https://twinery.org/) story, written in Harlowe or SugarCube, to Squiffy. Give it Twine's published or archive HTML file, or a Twee file:

```bash
npx @textadventures/squiffy-cli mygame.html --convert-twine
```

This creates a folder next to the file, with the same name (`mygame` here), with the Squiffy story in it, and `twine-import.txt`, which lists anything that couldn't be converted exactly. To put it somewhere else, add `--out` and a folder that's empty or doesn't exist yet. See [Coming from Twine](/coming-from-twine/) for what's converted, and how.

### Converting from Squiffy 6

In a story with a `squiffy.json`, text in `@set` and link assignments goes in quotes, and attributes are written without an `@` (see [Coming from Squiffy 6](/whats-new-7/#coming-from-squiffy-6)). A Squiffy 6 story has no `squiffy.json`, so it keeps the old rules. When the CLI builds one whose assignments would need changing, it says so. Use `--convert-v6`, giving it the story's main file, to convert it and add a `squiffy.json`:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --convert-v6
```

This converts the main file and every `.squiffy` file it `@import`s, keeping each original as a `.bak` file. The new `squiffy.json` leaves out any other `.squiffy` files in the folder, so the story is made of the same files as before. Anything that can't be converted exactly is left as it is, and listed with its line number so you can update it by hand. If the story still has Squiffy 5 syntax, run `--convert-v5` first.

### Converting from Squiffy 5

Squiffy 6 replaced the Squiffy 5 text processor syntax, such as `{if x:...}` and `{x}`, with [Handlebars](/dynamic-text/). When the CLI sees Squiffy 5 syntax in a story, it warns about it. Use `--convert-v5` to convert it to the Squiffy 6 equivalent:

```bash
npx @textadventures/squiffy-cli mygame.squiffy --convert-v5
```

This updates `mygame.squiffy`, keeping the original as `mygame.squiffy.bak`. Anything that can't be converted reliably is left as it is, and listed with its line number so you can update it by hand. Files included with `@import` aren't converted, so run the CLI on each of them too.
